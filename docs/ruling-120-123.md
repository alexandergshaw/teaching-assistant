## RULING 120 (BL2) - three states, not two

`describeDropRubricOrigin` now takes a second argument, `rubricPresent`
(the caller passes `Boolean(drop.rubricText)`), because `originScope` alone
cannot distinguish "no rubric" from "a rubric whose origin was not
recorded" - and the second state is reachable on every pre-migration row
plus the C9 path (course/assignment labels blank at upload time).

Three states, in the order the function checks them:

1. `!rubricPresent` -> `FROZEN_NO_RUBRIC` = "No rubric was included with
   this upload." (unchanged, still pinned by string equality).
2. `rubricPresent && !originScope` -> a new frozen sentence,
   `FROZEN_RUBRIC_ORIGIN_UNKNOWN` = "A rubric was included with this
   upload, but its source was not recorded." (new; pinned by string
   equality the same way).
3. `rubricPresent && originScope` -> unchanged, "Rubric from
   `<humanised scope>`."

`present` in the return value now tracks `rubricPresent` (true in states 2
and 3). It has no production consumer - the render at
`CartridgeDropPanel.tsx` reads only `.text` - and its JSDoc now says so
explicitly, so it is not mistaken for load-bearing. Kept exported because
the test suite uses it to assert the presence branch without parsing
prose.

The 11-case oracle in `rubric-origin.test.ts` (R3, unchanged - it tests
`resolveRubricOriginScope`, the scope *decision*, not the render) still
returns `null` for C9; what changed is what `describeDropRubricOrigin`
renders when it receives that `null` together with `rubricText` present.
Added end-to-end coverage for exactly that combination in
`cartridge-drops.origin.test.ts`: the C9 path (typed rubric, blank
assignment label) and the pre-migration row shape (historical row with
`rubric_text` set and `rubric_origin_scope` null, read through
`listCartridgeDrops`) both render `FROZEN_RUBRIC_ORIGIN_UNKNOWN`, not
`FROZEN_NO_RUBRIC`.

`rubric-origin.test.ts`'s R4 block was rewritten for the three states:
R4a/R4b (state 1), a new R4a2 (state 3), R4c/R4d/R4e/R4f/R4g/R4h/R4j
updated to pass `rubricPresent: true` where they exercise a scoped origin.
R4g's pairwise-distinct check now covers five outputs, not four.

## RULING 123 - MA1 and MA2

**MA1.** R5b's framing claimed to catch "any NEW token, of any kind", but
the instrument was a four-name enumeration that a native
`<details>`/`<summary>` disclosure (adding a click - the exact thing
RULING 100 forbids) passes. Replaced with a tally of every `<Identifier`
token in the source (`/<[A-Za-z][A-Za-z0-9]*/g`, the check's own suggested
regex) frozen as an exact multiset. This is intentionally over-inclusive -
it also catches the file's TS-generic angle-bracket tokens
(`useState<CartridgeDrop[]>`, `useRef<HTMLInputElement>`, etc.) and one
angle-bracket pair inside a comment - which makes the instrument MORE
sensitive, never less: any one of those tokens changing also fails it. A
new `R5b-mutation-witness` test proves a `<details>/<summary>` splice
changes the tally.

**MA2.** R4j is the only assertion able to detect a second, independent
humaniser, but the notes' own mutants deleted the import outright - a
different mutant than the one R4j exists for, which coexists with a
retained import. Built the real one in a standalone probe (not committed;
`ma2-probe.mjs` in the scratchpad), keeping the import "retained" and
substituting a second parse for the branch in both forms named: split-on-
separator and lazy-group. Both go RED on R4j while the "import retained"
identity check stays green, exactly as the notes require:

```
REAL              : R4j=true  text(cartridge:A|B|C)="Rubric from A|B / C."
MUT_T split-on-bar: R4j=false text(cartridge:A|B|C)="Rubric from A / B|C."
MUT_U lazy-group  : R4j=false text(cartridge:A|B|C)="Rubric from A / B|C."
```
