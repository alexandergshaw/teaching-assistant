- **Lossless export-sourced zip.** Today an export-sourced `.zip` carries the
  export's text AS PARSED, and every item is flagged in the manifest as reduced
  fidelity, because the text was already tag-stripped and truncated to 3000
  chars at parse time. The right eventual answer is copying the ORIGINAL
  resource entries byte-for-byte out of the stored cartridge (resource-href
  mapping into the stored zip). Deliberately not in that slice. REGRESSION 274.
- **The sibling syllabus button still guesses.** "Generate syllabus" resolves
  Start Here ELSE the first module; the acknowledgement quiz now asks. One
  button in the group asks and the other guesses. Changing it touches a second
  frozen criterion (`lms-tab-syllabus-buttons-acceptance-criteria.md` B2-7).
  REGRESSION 276.
- **`useLmsGeneration`'s post-target picker persists nothing.**
  `postModuleChoice`, `postNewModuleName` and `templateId` are plain `useState`
  with no `ta-` key, violating the standing "every control survives a reload"
  rule. The acknowledgement quiz's new picker follows the correct precedent
  (`BulkCreateModulesModal`); this one does not.
- **Three upload paths still lack a client-side pre-flight**: the
  syllabus-adaptation inputs (`useSyllabusAdaptation.ts`), the `.pptx` deck
  extraction (`useDeckMode.ts`), and `src/app/account/voice-style/page.tsx` -
  that last one caps **7MB of RAW FILE bytes per file for up to five files**,
  the exact unit error the wire-budget round existed to eliminate, missed
  because a sibling page was fixed and it was not. REGRESSION 275.

## Landmines - read before touching these areas

- **`getFilePreview` is NOT a file-bytes path.** It returns base64 for `image/*`
  and `application/pdf` only, explanatory prose for everything else, and reports
  an over-15MB file as `truncated: false`. `getCanvasFileBuffer` is the only
  real bytes function, is server-only, and has a hard 15MB ceiling of its own.
- **`createThrottleBudget` is not a concurrency primitive.** It is a shared
  sleep budget for retry backoff; every existing caller runs sequentially.
- **A capability can ship completely dead with every gate green.** The
  export-download path did: `ContentTab.tsx` blanks `courseUrl` for every
  export-viewed course, and an availability check read it before `source`. Suite,
  tsc, lint and build were all green. Trace a feature from the control the user
  touches to the code, through the gating conditions.
- **`.ccStickyHeader` is a stacking context AND a containing block for
  `position: fixed`.** Anything rendered from `ModulesHeaderBar` or the bulk bar
  that is an overlay will paint behind the app chrome at header size. The
  existing guard test only checks ONE level deep.
- **`ContentTab.tsx` hardcodes `hasLiveCourse: source !== "export"`**, so an
  export view of a course that also has a live Canvas link gets the stricter
  gating reason. Known, separate.
- **`useLmsGeneration.ts` is at 951 lines** against the hard 1000-line cap.
- **REGRESSION line ~1346 is stale**: it says `ModulesView.tsx` is a ~638-line
  orchestrator with 8 components; it is 840 with 9.
